# トラブルシューティング（GAS AIブログ記事自動生成）

> Claude.ai 上の資料「トラブルシューティング」の内容を、GitHub で読めるよう Markdown に転記したものです（2026-11-12 時点）。関連資料：[使い方マニュアル](USER_MANUAL.md) ／ [APIキー設定手順書](API_KEY_SETUP.md)

## この資料の使い方

表示されたメッセージの文言で、下の表の「症状」列を探してください。掲載しているのは、現在のスクリプトの実装に含まれるメッセージだけです。実装から発生条件を確かめられない部分は「未確認」と書いています。

メッセージが出る場所は2か所あります。

| 場所 | 内容 |
| --- | --- |
| 画面のメッセージ（ダイアログ） | メニューの処理が終わったときに表示されます。記事生成中のエラーは「エラーが発生しました（○行目）。」に続けて理由が表示されます。対象の行が決まる前のエラーでは「（○行目）」は付きません。接続テストの失敗は「接続テスト失敗」に続けて表示されます |
| 「生成ログ」シートの「メッセージ」列 | ダイアログを閉じた後でも確認できます。「対象行」と「実行ID」で、どの行・どの実行の記録かを探せます |

表の「○」「…」の部分には、行番号や文字数などの実際の値が入ります。APIキーに関する対処は、別紙「[APIキー設定手順書](API_KEY_SETUP.md)」を参照してください。

## 設定・入力の問題

設定や入力に不備があるときは、AIへの依頼は行われず、費用もかかりません。

| 症状（表示されるメッセージ） | 原因 | 対処 |
| --- | --- | --- |
| 「エラーが発生しました。」に続けて「次の設定が未登録です: …。メニュー「記事生成」から設定してください。」 | 「…」に表示された設定（APIキー・対象シート名・入力単価・出力単価）が未登録 | APIキーは「APIキー設定手順書」を参照。単価は「記事生成」→「単価を設定」、対象シートは「記事生成」→「対象シート名を設定」で登録する |
| 接続テストで「接続テスト失敗 APIキーが未設定です。」 | APIキーが未登録 | 「APIキー設定手順書」の手順2で登録する |
| 「単価の形式が不正です: …（0以上の数値で入力してください）」 | 単価に数字以外（`$` やマイナスなど）を入力した | 「単価を設定」で、`1.5` のように数字だけを入力し直す。このとき単価は変更されていません |
| 「対象シート名を設定」で「シート「…」が見つかりません。保存しませんでした。」 | 入力した名前がタブ名と一致しない（数字の全角・半角など） | 画面下のタブをダブルクリックして名前をコピーし、`Esc` で編集を終えてから貼り付ける |
| 「エラーが発生しました。」に続けて「対象シート「…」が見つかりません。メニュー「記事生成 > 対象シート名を設定」で設定してください。」 | 登録後にタブ名が変わった、またはシートが削除された | 「対象シート名を設定」で今のタブ名を登録し直す |
| 「○行目: A列（キーワード）が空のため生成できません。ステータスを「エラー」にしました。」（D列のときは「D列（タイトル）」、両方のときは「A列（キーワード）・D列（タイトル）」）。生成ログは種別「入力チェック」、結果「エラー」 | 「未処理」の行で、A列またはD列が空欄。C列は「エラー」になる | A列・D列を入力し、「[やり直しの手順](#やり直しの手順)」で実行し直す |
| 「処理対象の「未処理」行はありません。」 | C列が「未処理」で、F列・G列が空欄の行がない | 生成したい行のC列に「未処理」と正しく入力されているか、F列・G列が空欄かを確認する |
| ほかのメッセージの末尾に「スキップした「未処理」行（既存データ保護）:」と「○行目（F列（本文）に既存データあり）」（G列のときは「G列（メタディスクリプション）に既存データあり」）。生成ログは種別・結果とも「スキップ」 | 「未処理」なのにF列かG列に値があるため、既存データを守って飛ばした。表示されるのは、生成対象の行より上にある行だけ | その値が不要なら空欄にしてから実行する。必要ならC列を「未処理」以外にする |
| 「別の生成処理が実行中です。終了してから再度実行してください。」 | 別の人または別の画面で生成を実行中 | その処理が終わってから実行する |

## 生成内容の問題

AIが作った文章が条件を満たさないときは、「生成ログ」の結果が「NG」になり、自動で**最大1回**作り直されます。作り直しで条件を満たせば、C列は「生成済み」になり、対処は不要です。作り直した分も費用がかかります。

| 症状（生成ログのメッセージ） | 原因 | 対処 |
| --- | --- | --- |
| 「本文の文字数（HTMLタグ除く）が ○ 字です。2000〜3000 字にしてください。」 | 本文の文字数の不足または超過 | 自動で作り直される。同じ実行IDの「再生成」の行で結果を確認する |
| 「メタディスクリプションが ○ 字です。120 字以内にしてください。」。ほかに「メタディスクリプションが空です。」「メタディスクリプションにHTMLタグは使えません。」「メタディスクリプションに文字参照（`&amp;` など）は使えません。」「メタディスクリプションの先頭に「= + - @」は使えません。」「メタディスクリプションに Markdown 記法（例:「…」）は使えません。…」 | メタディスクリプションが長すぎる、空、または書式が条件と違う | 同上 |
| 「Markdown の見出し記法（例:「…」）が含まれています。…」など、Markdown・箇条書き・強調・コード記法・リンクに関するメッセージ | 本文にHTML以外の書式（`##`、`**` など）が混ざった | 同上 |
| 「タグが記号表記（例:「…」）で書かれており…」「閉じられていないタグがあります…」など、タグの書き方に関するメッセージ | 本文のHTMLの構造が壊れている（二重タグ、閉じ忘れなど） | 同上 |
| 「使用できないタグ `<…>` が含まれています…」「`<…>` に属性は付けられません。」「HTMLコメントや `<!DOCTYPE>` などの特殊構文は使えません。」 | 許可していないタグや属性を使った | 同上 |
| 「`<h2>` 見出しがありません。」「最後の `<h2>` 見出しを「まとめ」にしてください。」「本文はHTMLタグ（`<p>` または `<h2>`）で始めてください。」「本文（body_html）が空です。」 | 記事の構成が条件と違う | 同上 |
| 「出力が上限トークン数で途中終了しました（stop_reason: max_tokens）。」 | AIの出力が長すぎて途中で切れた | 同上 |
| 「応答をJSONとして解析できませんでした。」「応答にテキストが含まれていません。」「応答JSONに body_html / meta_description がありません。」 | AIの応答が決められた形式でなかった | 同上 |
| 画面に「エラーが発生しました（○行目）。2回生成しても条件を満たしませんでした: …」。生成ログは「生成」「再生成」がともにNG、「記事合計」がエラー | 作り直しても条件を満たさなかった。C列は「エラー」になり、F列・G列には何も書き込まれない | 「やり直しの手順」でもう一度実行する。同じ理由で繰り返し失敗する場合は、「[解決しないとき](#解決しないとき)」のとおり連絡する |

「○」「…」の部分には、実際の文字数や問題のあった箇所の文字列が入ります。1回の結果に複数のメッセージが並ぶこともあります。作り直しのときは、見つかった問題がAIに伝えられます。

## 処理の停止・通信の問題

この表の問題は自動では作り直されません（一時的なHTTPエラーの一部は、メッセージが出る前に自動で最大3回再送されています）。どの場合も、すでにF列・G列に入っている内容が消されることはありません。

| 症状（表示されるメッセージ・状態） | 原因 | 対処 |
| --- | --- | --- |
| C列が「生成中」のまま変わらず、完了メッセージもエラーメッセージも表示されない | まだ処理中であるか、処理が途中で終わってステータスを更新できなかった。通常のエラーではC列は「エラー」に変わるため、「生成中」のまま残る具体的な条件は未確認。「生成中」の行は自動ではやり直されない | すぐにC列を書き換えない。メニューを実行してから10分以上たっても「生成中」のままなら、「やり直しの手順」で実行し直す |
| 「実行時間の上限に近づいたため中止しました。」 | 1回の実行に使える時間を使い切りそうになった。C列は「エラー」になる | 時間を置いて「やり直しの手順」で実行し直す |
| 「Claude API への通信に失敗しました: …」 | 一時的な通信障害や応答のタイムアウト。二重の請求を避けるため、自動では再送しない | 時間を置いて「やり直しの手順」で実行し直す |
| 「Claude API エラー (HTTP ○): …」。生成ログの結果は「APIエラー」 | Claude API がエラーを返した。エラーの内容は「…」の部分に表示される（接続テストでも同じ形で表示される） | 「APIキー設定手順書」の「困ったとき」に同じメッセージがあれば、その対処を行う。それ以外は、「解決しないとき」のとおり連絡する |
| 「モデルが応答を拒否しました（stop_reason: refusal）。」 | AIがこの題材での応答を断った。自動では作り直さない（生成ログの結果は「NG」） | 「解決しないとき」のとおり連絡する |
| 「想定外の stop_reason です: …」「API応答のJSONを解析できませんでした。」 | APIから想定していない形の応答が返った | 「解決しないとき」のとおり連絡する |
| 「○行目の状態が変わったため処理を中止しました。」「書き込み前の確認で ○行目のステータスが「…」に変わっていたため、書き込みを中止しました。」「書き込み前の確認で ○行目のF列またはG列に値が入っていたため、上書きせず中止しました。」 | 生成の開始直前または生成中に、その行のC列・F列・G列が編集された。既存データを守るため書き込まなかった（1つ目のメッセージはAIへの依頼前なので費用はかからない） | その行の内容を確認する。生成し直す場合は「やり直しの手順」で実行する。生成中はその行を編集しない |

AIへの依頼が行われた後に中止した場合、その分の費用はかかっています。金額は「生成ログ」の「今回費用(USD)」と「記事合計費用(USD)」で確認できます。

## やり直しの手順

C列が「エラー」または「生成中」のままの行は、自動では生成されません。C列を「未処理」に戻すと、もう一度生成の対象になります。

**「生成中」の行は、まだ処理が動いている可能性があります。** メニューを実行してから10分たっていない場合は、C列を書き換えずに待ってください。スクリプトは、開始から5分を過ぎると新しいAIへの依頼を始めない作りです。また Apps Script には1回の実行時間の上限があります（Google の公開情報では6分。この環境での実測は未確認）。10分は、これらに余裕を持たせた目安です。

処理中に誤って「未処理」へ戻しても、元の処理は書き込み前の確認で中止され、本文は上書きされません。ただし、その処理の費用は無駄になります。元の処理が終わる前に「未処理を1件生成」を実行すると、「別の生成処理が実行中です。…」と表示され、新しい処理は始まりません。

1. 「生成ログ」シートで、その行（「対象行」が同じ番号）のいちばん下の記録を見て、「メッセージ」で原因を確認します。
2. 原因が入力の不備なら、A列（キーワード）やD列（タイトル）を直します。設定の不備なら、先に設定を直します。
3. F列とG列が空欄であることを確認します。値が入っていると、既存データを守るため生成されません。
4. C列を「未処理」に書き換えます。
5. 「記事生成」→「未処理を1件生成」を実行します。その行より上に「未処理」の行がある場合は、上の行から順に生成されます。
6. 完了メッセージとC列が「生成済み」になったことを確認します。

やり直すたびに、AIへの依頼分の費用がかかります。

## 解決しないとき

この資料の対処で解決しない場合は、サポート窓口にメールで連絡してください。「生成ログ」にはAPIキーは記録されていないため、該当する行の内容をそのまま共有できます。

メールに書いてほしいこと

- [ ] 発生した日時と、対象の行番号
- [ ] 画面に表示されたメッセージの文面
- [ ] 「生成ログ」の該当行の「実行ID」「種別」「結果」「メッセージ」「リクエストID」
- [ ] この資料を見て試した対処

送ってはいけないもの

- APIキーの値（`sk-ant-` で始まる文字列）
- Apps Script の「スクリプト プロパティ」画面や、APIキーの入力欄が写ったスクリーンショット

APIキーを誤って送ってしまった場合は、「[APIキー設定手順書](API_KEY_SETUP.md)」の「キーの交換・漏えい時の対応」に従って、すぐにキーを無効化してください。
