## はじめに

この手順書に沿って操作すると、Claude API のキーを安全に登録し、記事生成を使える状態にできます。プログラミングの知識は不要です。

| 項目 | 内容 |
| --- | --- |
| 対象者 | 記事生成用スプレッドシートを使う担当者 |
| 前提 | スプレッドシートに記事生成用のスクリプトが導入済みで、メニューに「記事生成」が表示されること |
| キーの保存先 | Apps Script のスクリプトプロパティ `ANTHROPIC_API_KEY`（コード・シート・ログには保存されません） |
| 所要時間 | 約15分が目安（実測ではありません） |

この手順書には実際のAPIキーは記載していません。文中の `sk-ant-…` は形式を示すための表記です。Claude Console と Google の画面（承認画面、Apps Script の設定画面）の表示名やボタン名は、このシステムの実装では確認できないため未確認です。本書の記載と違う場合は、実際の画面に従ってください。

## 事前に用意するもの

作業を始める前に、次の4つがそろっているか確認してください。

- [ ] Anthropic のアカウント（Claude Console にログインでき、支払い方法が登録済みであること）
- [ ] 記事生成用スプレッドシートの**編集権限**（スクリプトはシートとスクリプトプロパティに書き込みます）
- [ ] パソコンのブラウザ（Google Chrome など。スマートフォンでの設定はおすすめしません）
- [ ] 周りから画面を見られない作業環境（画面共有や会議の録画は止めておく）

APIキーはパスワードと同じくらい大切な情報です。キーを知っている人は誰でも、あなたの費用で Claude API を使えてしまいます。

## 手順1：Claude Console でAPIキーを発行する

このシステム専用のキーを新しく発行します。キーは**発行直後の1回しか表示されない**ため、手順2まで続けて作業してください。画面の表記は変わることがあるので、似た名前のボタンを探してください。

1. ブラウザで [Claude Console](https://platform.claude.com) を開き、ログインします。
2. （推奨）このシステム専用のワークスペースを作り、**利用額の上限（spend limit）**を設定します。専用ワークスペースの月額上限は、組織全体の上限より低く設定できます。Default Workspace（最初からあるワークスペース）には個別の上限を設定できないため、専用ワークスペースを作ってください。上限は想定外の利用を抑えるためのもので、キーが漏れたときの被害を完全には防げません。利用状況を定期的に確認し、漏えいが疑われたらすぐにキーを無効化してください（「[キーの交換・漏えい時の対応](#キーの交換漏えい時の対応)」を参照）。
3. メニューの「API Keys」を開き、「Create Key」を押します。
4. キーの名前を入力します。用途が分かる名前にしてください（例：`gas-blog-generator`）。2. で作ったワークスペースがあれば、それを選びます。
5. 表示されたキー（`sk-ant-` で始まる長い文字列）をコピーボタンでコピーします。手で書き写したり、メモ帳やチャットに貼り付けたりしないでください。
6. コピーしたら、すぐに手順2へ進みます。控えを残す場合は、パスワード管理ツールだけに保存します（「[APIキーを安全に保管・管理する方法](#apiキーを安全に保管管理する方法)」を参照）。

コピーを忘れて画面を閉じた場合は、そのキーを無効化して、新しいキーを発行し直してください。

## 手順2：スプレッドシートにAPIキーを登録する

キーはスプレッドシートのメニューから登録します。登録したキーは Apps Script のスクリプトプロパティ `ANTHROPIC_API_KEY` に保存され、シートのセルやログには書き込まれません。

1. 記事生成用のスプレッドシートを開き、ページを再読み込みします。
2. 上部メニューの「記事生成」→「APIキーを設定」を選びます。
3. **初回だけ**「承認が必要です」と表示されます。「続行」を押し、利用中の Google アカウントを選びます。
4. 「このアプリは Google で確認されていません」と表示された場合は、「詳細」→「（プロジェクト名）に移動」を選びます。Google の確認を受けていないスクリプトで表示される画面です（表示の有無と文言は未確認）。
5. このスクリプトが求める次の3つの権限が表示されることを確認し、「許可」を押します。権限の種類はスクリプトの設定で確認済みですが、画面の文言は Google の表示に従います。
    - このスプレッドシートの表示と編集
    - 外部サービスへの接続（Claude API との通信に使用）
    - ダイアログやメニューの表示
6. 承認後、もう一度「記事生成」→「APIキーを設定」を選びます。
7. 入力欄にキーを貼り付け（Mac は `⌘V`、Windows は `Ctrl+V`）、「OK」を押します。
8. 「APIキーを保存しました。」と表示されれば登録完了です。

入力欄では、貼り付けたキーがそのまま見える状態になります。貼り付けてから「OK」を押すまでの間、画面を他の人に見せないでください。

空欄のまま「OK」を押すと「空欄のため保存しませんでした。」と表示され、何も保存されません。「キャンセル」を押した場合も何も変わりません。入力した値の形式はチェックされず、空欄以外はそのまま保存されます。正しいキーかどうかは、手順3の「接続テスト」で確認します。

## 手順3：設定を確認して接続テストをする

登録したキーが使えるかを、画面にキーを表示しない方法で確かめます。接続テストは短い依頼を1回送るだけで、費用はごくわずかです。

### 3-1. 設定状況を確認する

1. 「記事生成」→「設定状況を確認」を選びます。
2. 「APIキー: 設定済み」と表示されればOKです。キーの中身はここにも表示されません。

### 3-2. 接続テストをする

1. 「記事生成」→「接続テスト」を選びます。
2. 「接続テスト成功」と、応答モデル（`claude-sonnet-5-5`）・トークン数・費用が表示されれば成功です。
3. 「生成ログ」シートに、種別「接続テスト」の行が1行追加されます。初回はこのシートが自動で作られます。ログにキーは記録されません。

単価が未登録の場合、費用は「計算不可（単価未設定）」と表示されます。接続自体は成功しています。単価は「記事生成」→「単価を設定」で登録してください。

接続テストは、単価や対象シート名が未登録でも実行できます。失敗した場合は「接続テスト失敗」に続けて理由が表示され、「生成ログ」に種別「接続テスト」、結果「エラー」の行が追加されます。対処は「[困ったとき](#困ったとき)」を見てください。

### 3-3. 古いプロパティ `CLAUDE_API_KEY` を削除する

以前のスクリプトは `CLAUDE_API_KEY` という名前でキーを保存していました。現在は使われていないため、削除してください。

この削除は、Apps Script に残った値を消すだけの操作です。**キーそのものは無効にならず、値を知っていれば引き続き使えます。** キーを使えなくするには、Claude Console の「API Keys」でそのキーを無効化または削除する別の操作が必要です。`CLAUDE_API_KEY` に入っていたキーを今後使わない場合は、Claude Console でも無効化してください。

1. スプレッドシートの「拡張機能」→「Apps Script」を開きます。
2. 左側の歯車アイコン「プロジェクトの設定」を開き、下の「スクリプト プロパティ」までスクロールします。
3. 「スクリプト プロパティを編集」を押し、`CLAUDE_API_KEY` の行だけ「削除」して「スクリプト プロパティを保存」を押します。

`ANTHROPIC_API_KEY`、`DATA_SHEET_NAME`、`PRICE_` で始まる行は現在使っている設定です。削除しないでください。この画面では値がそのまま表示されるため、作業中は画面を他の人に見せないでください。

## APIキーを安全に保管・管理する方法

APIキーの正しい保存場所は、スクリプトプロパティと、必要ならパスワード管理ツールの2か所だけです。

| 保存場所 | 可否 | 理由 |
| --- | --- | --- |
| スクリプトプロパティ（メニュー「APIキーを設定」で登録） | ○ | スクリプトがキーを読む唯一の場所。シートのセルやログには表示されない |
| パスワード管理ツール（1Password、Bitwarden など） | ○ | 控えを残す場合の保存先。暗号化される |
| スプレッドシートのセル・メモ・コメント | × | 共有された全員が読める。変更履歴にも残る |
| スクリプトのコード（`.gs` ファイル） | × | コードを見る人や GitHub に漏れる |
| メール・チャット・チケット・共有ドキュメント | × | 送信履歴や検索に残り、消せない |
| パソコンのメモ帳・デスクトップのファイル | × | 暗号化されず、バックアップや同期で広がる |

管理のルール

- **専用のキーを使う**：このシステムだけに使うキーを発行し、他の用途と共用しません。漏れたときにこのキーだけを止められます。
- **利用額の上限を設定する**：Claude Console で専用ワークスペースに、組織全体より低い月額上限を設定し、想定外の利用を抑えます（Default Workspace には個別の上限を設定できません）。上限があっても被害がなくなるわけではないため、利用状況を定期的に確認してください。
- **編集者を絞る**：スクリプトプロパティは、このスクリプトを使う全員で共有される1つの設定です（利用者ごとに別のキーにはなりません）。スプレッドシートの編集者は Apps Script を開いてキーを見たり変更したりできるため、編集権限は必要な人だけに限定し、他の人は「閲覧者」にしてください。
- **コピーに注意する**：スプレッドシートを「コピーを作成」すると、スクリプトも複製されます。コピーを他の人に渡す前に、コピー側のスクリプトプロパティにキーが入っていないか確認してください（コピー時にスクリプトプロパティも複製されるかは未確認です）。
- **定期的に交換する**：担当者の変更時や半年に1回など、時期を決めてキーを交換します（手順は最後の章）。

## キーを画面やログに表示しないための注意点

このスクリプトは、登録後のキーを画面やログに表示・記録しない作りです（Claude API から返ってきたエラー文は、そのまま表示します）。ただし、登録する瞬間と管理画面ではキーがそのまま見えるため、その場面だけ注意が必要です。

| 場面 | キーの表示 | 注意点 |
| --- | --- | --- |
| 「設定状況を確認」 | 「設定済み」「未設定」だけ | 安心して使えます |
| 「生成ログ」シート・エラーメッセージ | 表示されない | 問い合わせにはこの内容を共有してください |
| 「APIキーを設定」の入力欄 | **そのまま見える** | 画面共有・録画・スクリーンショットをしない |
| Apps Script の「スクリプト プロパティ」 | **そのまま見える** | 必要なときだけ開き、すぐに閉じる |
| Claude Console のキー発行画面 | **発行時に1回だけ見える** | コピーしたらすぐに閉じる |

やってはいけないこと

- キーが写った画面を、手順書・問い合わせ・チャット用にスクリーンショットを撮る。
- スクリプトに `Logger.log` や `console.log` を追加して、キーやスクリプトプロパティを表示する。Apps Script の「実行数」画面に記録が残ります。
- キーを確かめるために、スプレッドシートのセルへ貼り付ける。削除しても変更履歴に残ります。
- キーが正しいかを「目で見て」確かめる。確認は「接続テスト」で行います。

貼り付けが終わったら、別の文字をコピーしてクリップボードからキーを消してください。クリップボード履歴の機能（Windows の `Win+V` など）を使っている場合は、履歴からも削除します。

## 困ったとき

表示されたメッセージを、下の表の左列で探してください。解決しない場合は、「生成ログ」シートの該当行（キーは記録されていません）を添えて、サポート窓口にメールで連絡してください。メールにはAPIキーの値を書かないでください。

| 表示されるメッセージ・状態 | 主な原因 | 対処 |
| --- | --- | --- |
| メニューに「記事生成」が出ない | ページの読み込み直後 | 数秒待つか、ページを再読み込みする |
| 「承認が必要です」 | 初回の権限承認がまだ | 手順2の 3.〜5. で承認する |
| 「エラーが発生しました。」に続く「次の設定が未登録です: APIキー…」、または「接続テスト失敗」に続く「APIキーが未設定です。」 | キーが登録されていない | 手順2で登録する |
| 「Claude API エラー (HTTP 401): authentication_error…」 | キーの貼り付け間違い、無効化済みのキー | 新しいキーを発行し、手順2で登録し直す（上書きされます） |
| 「Claude API エラー (HTTP 400)」で credit balance を含む | クレジット残高の不足 | Claude Console の請求設定で残高を確認する |
| 「Claude API エラー (HTTP 429)」 | 利用額の上限または利用回数の制限に達した | 時間を置き、上限に達していれば Console で見直す |
| 「Claude API への通信に失敗しました」 | 一時的な通信障害、応答のタイムアウト | 時間を置いてもう一度実行する |

HTTPエラーの番号（401・400・429）と原因の対応は Claude API の仕様によるもので、このシステムでは未確認です。メッセージの「…」の部分に表示される内容もあわせて確認してください。HTTP 429 などの一時的なエラーは、画面に表示される前に自動で最大3回再送されています。通信の失敗は自動では再送されません。

キーを登録し直した後は、必ず「接続テスト」で動作を確認してください。

## キーの交換・漏えい時の対応

定期交換は「新しいキーを登録してから古いキーを止める」、漏えい時は「まず古いキーを止める」の順です。どちらもスプレッドシート側はメニューから登録し直すだけで、コードの変更は不要です。

### 定期的に交換するとき

1. Claude Console で新しいキーを発行します（手順1）。
2. 「記事生成」→「APIキーを設定」で新しいキーを登録します。古いキーは自動で上書きされます。
3. 「接続テスト」で成功を確認します。
4. Claude Console で古いキーを無効化または削除します。

### キーが漏れたかもしれないとき

チャットへの誤投稿、セルへの貼り付け、キーが写った画面の共有などに気づいたら、すぐに次の順で対応してください。

1. **最初に** Claude Console でそのキーを無効化または削除します。この時点で記事生成は止まりますが、不正利用を止めることを優先します。スクリプトプロパティからキーを消したり上書きしたりするだけでは、漏れたキーは使えるままです。
2. 新しいキーを発行し、「APIキーを設定」で登録して「接続テスト」をします。
3. Claude Console の利用状況で、身に覚えのない利用がないか確認します。あれば Anthropic のサポートに連絡します。
4. 漏れた場所（チャットの投稿、セル、ファイルなど）からキーを削除します。スプレッドシートのセルに貼った場合は変更履歴にも残るため、キーの無効化（1.）が必須です。
5. スプレッドシートの編集者を見直し、不要な人の編集権限を外します。
6. サポート窓口に、気づいた日時と対応内容をメールで報告します。メールにはAPIキーの値を書かないでください。
