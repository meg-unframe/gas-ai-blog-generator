# GAS AIブログ記事自動生成

Googleスプレッドシートに入力したキーワードとタイトルから、Claude API（`claude-sonnet-5-5`）でブログ記事の本文（HTML）とメタディスクリプションを作る Google Apps Script です。スプレッドシートのメニュー「記事生成」から、1回の実行で1件ずつ生成します。WordPress への投稿は自動では行いません。

## 納品資料

詳しい手順は、`docs/` フォルダの次の3つの資料にまとめています。

| 資料 | 内容 |
|---|---|
| [使い方マニュアル（docs/USER_MANUAL.md）](docs/USER_MANUAL.md) | 入力する列、生成手順、結果と生成ログの確認方法 |

| [トラブルシューティング（docs/TROUBLESHOOTING.md）](docs/TROUBLESHOOTING.md) | 画面と生成ログのメッセージごとの原因と対処 |

これらは Claude.ai 上で作成した資料を、GitHub で読めるよう Markdown に転記したものです（2026-11-12 時点）。この README は、上の資料と現在の実装（`src/`）の要点をまとめたものです。実装から確かめられない事項は「未確認」と書いています（末尾の「未確認の事項」）。

## 概要

| 項目 | 内容 |
|---|---|
| 列 | A:キーワード / B:サブキーワード / C:ステータス / D:タイトル / E:WordPress URL / F:記事本文 / G:メタディスクリプション |
| 見出し行 | 1行目（データは2行目以降） |
| 実行 | メニュー「記事生成 > 未処理を1件生成」。C列が「未処理」で F・G 列が空の行のうち、いちばん上の1行だけを処理 |
| ステータス | 未処理 → 生成中 → 生成済み ／ 失敗時は エラー（A・D 列が空の行は「生成中」を経ずに「エラー」） |
| 書き込む列 | C・F・G のみ。A・B・D・E 列は書き換えない（D のタイトルは入力済みのものを使う。E は手入力用） |
| 本文 | HTML（`h2` `h3` `p` `ul` `ol` `li` `strong` のみ、属性なし）。最後の `h2` は「まとめ」。HTMLタグを除いて 2,000〜3,000 字 |
| メタディスクリプション | プレーンテキスト 120 字以内 |
| 作り直し | 条件を満たさない場合は自動で最大1回（API 呼び出しは合計2回まで） |
| モデル | `claude-sonnet-5-5`、effort `medium`、フォールバック（別モデルへの自動切り替え）なし |
| 記録 | 「生成ログ」シート（最初の記録時に自動作成。既存のシートは変更しない） |
| WordPress | 自動投稿はしない。F・G 列の内容を手作業で投稿し、URL を E 列に手入力する |

### 文字数の数え方

- 本文：HTMLタグを除く → 文字参照（`&amp;` `&nbsp;` `&#…;` など）を1文字に戻す → 改行・タブを除く → `Array.from(text).length`。スペースは数えます。シートの `LEN` 関数はタグも数えるため、正式な字数は生成ログの「本文文字数」で確認します。
- メタディスクリプション：プレーンテキストとして、改行・タブを除いて数えます。

### 自動で確認する内容

生成された文章は次の点を確認し、満たさない場合は生成ログの結果を「NG」にして、自動で最大1回作り直します。

- 本文の文字数、メタディスクリプションの文字数
- 本文が HTML タグで始まること、`h2` があり最後の `h2` が「まとめ」であること
- 使用できないタグ・属性・HTMLコメントなどがないこと
- 壊れた HTML（`&lt;p&gt;` のような記号表記のタグ、二重タグ・入れ子の誤り、閉じ忘れ、リスト構造の誤り、タグの外の文章）がないこと
- Markdown 記法（`##` 見出し、`**` 強調、`- ` 箇条書き、コード記法、`[文字](URL)` リンク）がないこと
- メタディスクリプションに HTML タグ・文字参照・Markdown がなく、先頭が `= + - @` でないこと

導入の段落や `h3` は AI への指示には含まれますが、自動の確認対象ではありません。

### 既存データの保護

- 「生成済み」「生成中」「エラー」の行は処理しません。「未処理」でも F・G 列に値がある行は飛ばします（ステータスも変えません）。
- 生成前に「未処理」→「生成中」にし、書き込む直前に「生成中のまま」「F・G 列が空のまま」かを確認します。変わっていれば書き込みません。
- エラーのときは C 列を「エラー」にするだけで、F・G 列は消しません。
- 同時実行はロックで防いでいます。

## 使い方

詳しくは「[使い方マニュアル](docs/USER_MANUAL.md)」を参照してください。

1. 記事データのシートで、2行目以降の空いている行に A 列（キーワード、必須）、B 列（サブキーワード、任意）、D 列（タイトル、必須）を入力し、F・G 列が空であることを確認します。
2. 最後に C 列へ「未処理」と入力します（前後の空白は無視されますが、ほかの文字が付いていると対象になりません）。
3. メニュー「記事生成」→「未処理を1件生成」を実行します。C 列が「生成中」になり、完了すると「○行目の記事を生成しました。」と、文字数・API 呼び出し回数・トークン数・推定費用が表示されます。
4. C 列が「生成済み」になったら、F 列（本文）と G 列（メタディスクリプション）を確認し、内容を人の目で確認します。
5. 次の記事は 3. から繰り返します。
6. WordPress への投稿は手作業で行い、投稿後の URL を E 列に入力します。

### 生成ログの見方

「生成ログ」シートには、AI への依頼1回ごとの記録（種別「生成」「再生成」）と、記事1件の結果をまとめた「記事合計」が記録されます。スキップ・入力チェック・接続テストの記録も同じシートに追加されます。同じ「実行ID」の行が1回分の記録です。

作り直しがあったかは、「記事合計」の行のメッセージが「API呼び出し 2 回」かどうかで確認できます。理由は同じ実行IDの「生成」の行のメッセージに、作り直し後の結果は「再生成」の行に記録されます。

## APIキー設定手順

詳しくは「[APIキー設定手順書](docs/API_KEY_SETUP.md)」を参照してください。APIキーの値は、この README・コード・シート・Git のどこにも書きません。

1. Claude Console で、このシステム専用の APIキーを発行します（推奨：専用ワークスペースを作り、組織全体より低い月額上限を設定。Default Workspace には個別の上限を設定できません）。
2. スプレッドシートのメニュー「記事生成」→「APIキーを設定」を選び、キーを貼り付けて「OK」を押します。初回は Google の権限承認が必要です。
3. 「記事生成」→「設定状況を確認」で「APIキー: 設定済み」と表示されることを確認します（キーの中身は表示されません）。
4. 「記事生成」→「接続テスト」で「接続テスト成功」と表示されることを確認します。
5. 以前のスクリプトが使っていたスクリプトプロパティ `CLAUDE_API_KEY` を、Apps Script の「プロジェクトの設定 > スクリプト プロパティ」から削除します。削除しても、そのキー自体は無効になりません。今後使わない場合は Claude Console でも無効化してください。

### APIキーの扱い

- 保存先はスクリプトプロパティ `ANTHROPIC_API_KEY` だけです。スクリプトはキーを画面やログに表示・記録しません（Claude API から返ってきたエラー文はそのまま表示します）。
- 入力した値の形式はチェックされず、空欄以外はそのまま保存されます。正しいキーかどうかは接続テストで確かめます。
- スクリプトプロパティは、このスクリプトを使う全員で共有される1つの設定です。スプレッドシートの編集者は Apps Script を開いてキーを見たり変更したりできるため、編集権限は必要な人だけに限定してください。
- 「APIキーを設定」の入力欄と、Apps Script のスクリプトプロパティの画面では、キーがそのまま表示されます。画面共有・録画・スクリーンショットをしないでください。
- 月額上限は想定外の利用を抑えるためのもので、漏えいの被害を完全には防げません。利用状況を定期的に確認し、漏えいが疑われたら最初に Claude Console でキーを無効化してから、新しいキーを登録し直してください。

### その他の初期設定

APIキーのほかに、次の2つも「記事生成」メニューから登録します。未登録の場合、記事生成は「次の設定が未登録です: …」と表示して止まります。

- **単価を設定**：`claude-sonnet-5-5` の単価を公式の料金ページ（https://platform.claude.com/docs/en/about-claude/pricing ）で確認し、100万トークンあたりの米ドルで入力します。入力・出力は必須、キャッシュは任意です。単価はコードに書いていないため、料金改定時はここを更新してください。
- **対象シート名を設定**：A〜G 列のデータがあるシート名を入力します。見た目が同じでも全角・半角などが違うと一致しないため、タブ名をコピーして貼り付けるのが確実です。

## 費用の確認方法

API 呼び出しごとに、応答の `usage`（入力・出力・キャッシュのトークン数）、実際の応答モデル、登録した単価、その回の費用を「生成ログ」に記録します。記事1件の「記事合計」には、作り直し分を含む合計費用を記録します。

```
費用(USD) = Σ (トークン数 × 登録単価 / 1,000,000)
```

- 出力トークンには thinking（内部推論）の分も含まれます。
- 単価が未登録のトークン種別があると、費用は「計算不可（単価未設定）」（ログでは空欄）になり、メッセージ欄に警告が出ます。
- プロンプトキャッシュは使っていないため、通常キャッシュのトークンは 0 です。

## トラブルシューティング

詳しくは「[トラブルシューティング](docs/TROUBLESHOOTING.md)」を参照してください。主なメッセージは次のとおりです。

| メッセージ・状態 | 原因 | 対処 |
|---|---|---|
| 「エラーが発生しました。」に続く「次の設定が未登録です: …」 | APIキー・対象シート名・入力単価・出力単価のいずれかが未登録 | 「APIキー設定手順書」と「記事生成」メニューで登録する |
| 「処理対象の「未処理」行はありません。」 | C 列が「未処理」で F・G 列が空の行がない | 入力内容を確認する |
| 「スキップした「未処理」行（既存データ保護）」 | 「未処理」なのに F・G 列に値がある | 不要なら空欄にする |
| 「○行目: A列（キーワード）…が空のため生成できません。ステータスを「エラー」にしました。」 | A 列または D 列が空 | 入力して C 列を「未処理」に戻す |
| 「別の生成処理が実行中です。終了してから再度実行してください。」 | 生成が実行中 | 終わってから実行する |
| 生成ログの結果「NG」（文字数・書式などのメッセージ） | AI の文章が条件を満たさない | 自動で最大1回作り直される |
| 「エラーが発生しました（○行目）。2回生成しても条件を満たしませんでした: …」 | 作り直しても条件を満たさない（C 列は「エラー」、F・G 列は書き込まれない） | C 列を「未処理」に戻して再実行する |
| 「Claude API への通信に失敗しました: …」 | 通信エラーやタイムアウト（自動では再送しない） | 時間を置いて再実行する |
| 「Claude API エラー (HTTP ○): …」 | Claude API がエラーを返した（一時的なエラーの一部は表示前に最大3回再送済み） | 「APIキー設定手順書」の「困ったとき」を参照する |
| C 列が「生成中」のまま変わらない | まだ処理中か、処理が途中で終わった（具体的な条件は未確認） | 下記の注意を参照 |

### 「エラー」「生成中」の行をやり直す

1. 「生成ログ」で原因を確認し、入力や設定の不備を直します。
2. F・G 列が空であることを確認し、C 列を「未処理」に戻します。
3. 「記事生成」→「未処理を1件生成」を実行します。

**「生成中」の行は、まだ処理が動いている可能性があります。** メニューを実行してから10分たつまでは、C 列を書き換えないでください。スクリプトは開始から5分を過ぎると新しい AI への依頼を始めません（Apps Script の1回の実行時間の上限は、Google の公開情報では6分。この環境での実測は未確認）。誤って処理中に「未処理」へ戻しても、元の処理は書き込み前の確認で中止され、本文は上書きされませんが、その処理の費用は無駄になります。

解決しない場合は、生成ログの該当行（日時・実行ID・種別・結果・メッセージ・リクエストID）を添えて、サポート窓口にメールで連絡してください。生成ログにはAPIキーは記録されていません。メールにAPIキーの値を書かないでください。

## 開発者向け

### clasp の準備（初回のみ）

clasp はこのプロジェクトの開発依存（`devDependencies`、バージョン固定）として入れています。グローバルインストールや `sudo` は不要です。

```bash
npm install            # clasp を node_modules に導入
npx clasp login        # ブラウザで Google アカウントにログイン
```

https://script.google.com/home/usersettings で「Google Apps Script API」をオンにします。

### スプレッドシートへの紐づけ

1. 対象のスプレッドシートで「拡張機能 > Apps Script」を開き、「プロジェクトの設定」からスクリプトIDをコピーします。
2. `cp .clasp.json.example .clasp.json` で設定ファイルを作り、`scriptId` を書き換えます（`.clasp.json` は Git の対象外です）。

> ⚠️ `clasp push` は Apps Script 側のファイルを `src/` の内容で置き換えます。紐づけ先に別のコードがある場合は消えるため、push 前に Apps Script エディタで中身を確認し、必要なら別フォルダに `npx clasp clone <スクリプトID>` でバックアップを取ってください。スプレッドシートのデータとスクリプトプロパティは、push では変更されません。

### テスト・反映

```bash
npm test        # 単体テスト（Validator・Cost・Prompt・応答解析。API は呼ばない・費用なし）
npx clasp push  # Apps Script へ反映（npm run push でも可）
```

### 動作確認チェックリスト

本番データを守るため、まずスプレッドシートのコピーで確認してください。

1. `npm test` がすべて成功する。
2. 「接続テスト」が成功し、生成ログに応答モデル・トークン数・費用が記録される。
3. 「未処理」1行で生成 → C・F・G 列以外が変わらない／「生成済み」になる／生成ログの「本文文字数」が範囲内／記事合計費用 = トークン数 × 単価。
4. F（または G）列に値がある「未処理」行が飛ばされ、内容・ステータスが変わらない。
5. D 列が空の行が「エラー」になり、API が呼ばれない（生成ログに費用が出ない）。
6. 誤った APIキーで「Claude API エラー (HTTP ○)」になり、F・G 列が消えない（HTTP の番号は Claude API の仕様によるもので未確認）。
7. 「生成済み」「エラー」の行に触れない。連続実行で次の1行が処理される。
8. 生成にかかる時間を確認する（`UrlFetchApp` はストリーミング非対応のため、応答が長いとタイムアウトする可能性があります）。
9. 本番シートで1件だけ実行し、内容と費用を確認してから運用する。

## 既存コードからの置き換え（実施済み）

紐づけ先の Apps Script には、以前のコード（選択行から生成する版。`CONFIG`・`SAMPLE_ARTICLE` を含む）がありました。`CONFIG` と `onOpen` の名前が衝突して共存できないため、無改変で `legacy/` に保存したうえで、本実装に置き換えました。以前のコードはスクリプトプロパティ `CLAUDE_API_KEY` を使っていたため、置き換え後は「APIキー設定手順」の 5. のとおり削除してください。
