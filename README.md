# GAS AIブログ記事自動生成

Googleスプレッドシートの「未処理」行から、Claude API（`claude-sonnet-5-5`）でブログ記事の本文（HTML）とメタディスクリプションを生成する Google Apps Script です。

## 仕様

| 項目 | 内容 |
|---|---|
| 列 | A:キーワード / B:サブキーワード / C:ステータス / D:タイトル / E:WordPress URL / F:記事本文 / G:メタディスクリプション |
| 見出し行 | 1行目（データは2行目以降） |
| 実行 | メニュー「記事生成 > 未処理を1件生成」で、上から最初の対象行を **1行だけ** 処理 |
| ステータス | 未処理 → 生成中 → 生成済み ／ 失敗時は エラー |
| 書き込む列 | C・F・G のみ（A・B・D・E は書き換えない。D のタイトルは入力済みのものを使う） |
| スキップ | 「未処理」でも F または G に既存データがある行はスキップ（ステータスも変更しない） |
| 入力エラー | A（キーワード）または D（タイトル）が空 → API を呼ばずに「エラー」 |
| 本文 | HTML（h2 / h3 / p / ul / ol / li / strong のみ、属性なし）。最後の h2 は「まとめ」。タグ除外で 2,000〜3,000 字 |
| メタ | プレーンテキスト 120 字以内 |
| 再生成 | 条件を満たさない場合は最大1回（API 呼び出しは合計2回まで） |
| モデル | `claude-sonnet-5-5`、effort `medium`、フォールバック（別モデルへの自動切り替え）なし |
| 記録 | 「生成ログ」シート（初回に自動作成。既存シートは変更しない） |

### 文字数の数え方

本文: HTMLタグを除去 → 文字参照（`&amp;` `&nbsp;` `&#…;` など）を1文字に戻す → 改行・タブを除去 → `Array.from(text).length`。スペースは数えます。
メタディスクリプション: プレーンテキストとして改行・タブを除いて数えます（タグ・文字参照は不可）。

### 既存データの保護

- 「生成済み」「生成中」「エラー」の行には触れません。
- 生成前に「未処理」→「生成中」にし、書き込み直前に「生成中のまま」「F・G が空のまま」かを再確認します。条件が崩れていれば書き込みません。
- エラー時は C を「エラー」にするだけで、F・G は消しません。
- 途中で止まり「生成中」のまま残った行は自動では再処理しません（内容を確認し、手動で「未処理」に戻してください）。
- 同時実行はロックで防止します。

## セットアップ

### 1. clasp の準備（初回のみ）

```bash
npm install -g @google/clasp
clasp login            # ブラウザで Google アカウントにログイン
```

https://script.google.com/home/usersettings で「Google Apps Script API」をオンにします。

### 2. 既存スプレッドシートへの紐づけ

1. 対象のスプレッドシートを開き「拡張機能 > Apps Script」を開く。
2. 「プロジェクトの設定」から **スクリプトID** をコピー。
3. このフォルダで設定ファイルを作成し、`scriptId` を書き換える。
   ```bash
   cp .clasp.json.example .clasp.json
   ```

> ⚠️ **`clasp push` は Apps Script 側のファイルをローカルの `src/` の内容で置き換えます。**
> 紐づけ先の Apps Script に既存のコード（例: 別の `onOpen`）がある場合は消えてしまうため、push 前に Apps Script エディタで中身を確認してください。既存コードがあれば、別フォルダに `clasp clone <スクリプトID>` でバックアップを取ってから進めてください。
> スプレッドシートのデータは push では変更されません。

### 3. テスト・反映

```bash
npm test      # 単体テスト（API は呼ばない・費用なし）
clasp push    # Apps Script へ反映
```

スプレッドシートを再読み込みすると「記事生成」メニューが表示されます。初回実行時に権限の承認画面が出ます。

### 4. 初期設定（メニュー「記事生成」から）

1. **APIキーを設定** — Anthropic Console で発行したキーを入力。
2. **単価を設定** — 公式の料金ページ（https://www.anthropic.com/pricing または https://platform.claude.com/docs/en/about-claude/pricing ）で `claude-sonnet-5-5` の単価を確認し、**100万トークンあたりの米ドル** で入力。入力・出力は必須、キャッシュは任意です。コードには単価を書いていません。料金改定時はここを更新してください。
3. **対象シート名を設定** — A〜G列のデータがあるシート名。
4. **設定状況を確認** — すべて設定済みか確認。

## APIキーの扱い

- APIキーは **スクリプトプロパティ**（`ANTHROPIC_API_KEY`）にのみ保存します。コード・シート・Git・ログには保存しません。
- **スクリプトの編集者はスクリプトプロパティを閲覧できます。** スプレッドシート／スクリプトの編集権限は必要最小限にしてください。
- この案件専用の APIキー（できれば専用ワークスペース）を作り、Anthropic Console で利用上限（spend limit）を設定してください。
- 漏えいが疑われたら Console でキーを無効化し、新しいキーを「APIキーを設定」で登録し直してください。

## 費用の確認方法

API 呼び出しごとに「生成ログ」へ、応答の `usage`（入力・出力・キャッシュのトークン数）、実際の応答モデル、登録単価、その回の費用を記録します。1記事の最後に「記事合計」行を追加し、再生成分も含めた合計費用を記録します。

```
費用(USD) = Σ (トークン数 × 登録単価 / 1,000,000)
```

- 出力トークンには thinking（内部推論）分も含まれます。
- 単価が未登録のトークン種別があると、費用欄は空欄（計算不可）になり、メッセージ欄に警告が出ます。
- 本ツールはプロンプトキャッシュを使っていないため、通常キャッシュのトークンは 0 です。

## 動作確認チェックリスト

本番データを守るため、まず **スプレッドシートのコピー** で確認してください。

1. `npm test` がすべて成功する。
2. 「接続テスト」が成功し、生成ログに応答モデル・トークン数・費用が記録される。
3. 「未処理」1行で生成 → C・F・G 以外が変わらない／「生成済み」になる／文字数が範囲内（例: `=LEN(F2)` はタグ込みなので参考値、正式な字数は生成ログの「本文文字数」）／記事合計費用 = トークン数 × 単価。
4. F（または G）に値がある「未処理」行がスキップされ、内容・ステータスが変わらない。
5. D が空の行が「エラー」になり、API が呼ばれない（生成ログに費用が出ない）。
6. 誤った APIキーで HTTP 401 → 「エラー」になり、F・G が消えない。
7. 「生成済み」「エラー」の行に触れない。連続実行で次の1行が処理される。
8. 生成にかかる時間を確認する（GAS の `UrlFetchApp` はストリーミング非対応のため、応答が長いとタイムアウトする可能性があります。発生した場合は生成ログに通信エラーとして記録されます）。
9. 本番シートで1件だけ実行し、内容と費用を確認してから運用する。

## ファイル構成

```
src/
  appsscript.json   タイムゾーン・V8・最小権限
  Config.gs         列番号・ステータス・文字数・モデル・再試行設定
  Main.gs           メニュー、1件生成のメイン処理
  SheetRepo.gs      対象行の選択、書き込み直前の再確認、C/F/G への書き込み
  ClaudeClient.gs   Messages API 呼び出し、HTTP 再試行、応答解析
  Prompt.gs         システムプロンプト、JSON Schema
  Validator.gs      文字数・タグ・構成の検証（純粋関数）
  Cost.gs           費用計算（純粋関数）
  Logger.gs         「生成ログ」シートへの記録
  Setup.gs          APIキー・単価・対象シートの設定、接続テスト
tests/
  validator.test.js Node の単体テスト
```
